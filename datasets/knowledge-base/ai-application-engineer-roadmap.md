# AI 应用工程师技术学习路径

最后更新：2026-08-28

## 结论与适用范围

AI 应用工程师的核心不是训基础模型，而是把模型能力做成**可上线、可评测、可降本、可迭代**的产品：会调模型、会管上下文、会让系统行动、会把效果和成本关进工程里。

本文面向已有后端 / 业务开发经验、要转到或加深「AI 应用」方向的人。按「能调用 → 能检索 → 能行动 → 能上线」四段递进。已有 Java / Spring / IoT / 业务中台经验时，L0 只补缺口，从 L1 起正式计时。

不覆盖：从零学编程、论文级预训练、CUDA 内核、当科学家发 paper。那些是相邻角色，后置即可。

## 角色边界

| 角色 | 交付物 | 主战场 | 先不要当成自己 |
|------|--------|--------|----------------|
| AI 应用工程师 | 能上线的智能功能 | Prompt / RAG / Agent / 评测 / 成本 / 网关 | 基础模型训练 |
| 后端 / 平台工程师 | 稳定、多端可复用的服务 | 领域模型、存储、网关、设备通道 | 「会调 API 就算 AI」 |
| 算法工程师 | 更好的模型或特征 | 训练、数据、评测集、推理优化 | 业务编排与产品化 |
| Prompt / 运营 | 话术与流程 | 人设、话术、场景脚本 | 系统架构与 SLO |

判断自己是否在做 AI 应用而不是「套一层 Chat」：有没有**结构化输出、工具调用、检索/记忆、评测、降级、配额**。缺这几项，仍是演示。

## 能力地图

四层，后一层以前一层为底座。

```text
L5–L6  上线与治理    评测 / 观测 / 成本 / 安全 / 网关 / 数据飞轮
L3–L4  行动与交互    Agent / 工具 / 工作流 / MCP / 语音与多模态
L2     上下文        切分 / 检索 / 重排 / 引用 / 记忆与过期
L1     模型使用      API / 流式 / 结构化输出 / Prompt / 多模型路由
L0     工程底座      Python 或等价 / HTTP 流式 / Docker / 日志与配置
```

横向再加三条，贯穿全程：

- **产品感**：什么该模型做、什么该规则/检索/人审做。
- **数据感**：坏 case 能沉淀成评测集，而不是只改一句 Prompt。
- **系统感**：超时、重试、降级、幂等、鉴权，与普通服务同一套纪律。

## 怎么用这份路径

1. 用文末「过关总表」自测，已会的层跳过，不会的层做一个最小交付再往下。
2. 每一层只做一个能跑通的项目，避免同时学三套框架。
3. 练习尽量落在真实业务形态上：会话、知识问答、语音、设备侧指令、运营配置。不要为学而另起一套用不上的玩具栈。
4. 主力若是 Java 8 / Spring Boot 2.x：模型层用**独立服务或网关**（Python / Go / 现成编排如 Dify），业务域仍留在现有 Java 服务。不要为了 Spring AI 强行升整个运行时。

建议节奏（在职、每周 8～12 小时）：L1 2～3 周 → L2 4～6 周 → L3 4～6 周 → L4 按需 → L5 贯穿后半段 → L6 结合线上功能。全职可压缩到 3～4 个月走到 L5。

## L0 工程底座

**目标：** 能独立起一个可部署的小服务，发出流式 HTTP，会看日志和配置。

已有后端经验则只补这三项：Python 异步（或 Go）、SSE / WebSocket 流式、向量库与 Docker 最小编排。Java 主栈不必换成 Python 全家桶。

必须掌握：

- 一门能快速写 AI 胶水层的语言：Python 3（优先 `uv`）或 Go。
- HTTP：超时、重试、取消、流式（SSE）；WebSocket 长连接有设备/语音场景时要熟。
- 配置与密钥：环境变量、分环境配置；密钥不进仓库。
- Docker：本地跑模型代理、向量库、观测组件。
- 日志：request id、model、token、耗时；没有这四样后面无法排障。

最小交付：一个本地服务，转发一次流式对话，日志里能看到 token 与耗时。

过关：能讲清「同步 HTTP、SSE、WebSocket」各自适合哪类 AI 接口；能在超时和上游 429 时做出可预期行为。

## L1 模型调用与 Prompt

**目标：** 把模型当成不可靠的函数：有输入契约、输出契约、失败模式和成本。

必须掌握：

- Token、上下文窗口、温度 / top_p、seed；何时必须低温度。
- 系统提示 vs 用户消息 vs 工具结果；多轮里如何控制上下文膨胀。
- **结构化输出**：JSON Schema / tool 参数；解析失败要重试或降级，禁止裸 `eval` 模型文本。
- 流式与非流式的产品差异（首 token、取消、断线续传）。
- 多模型：同一 OpenAI 兼容协议下切换；国内常见云（豆包 / DeepSeek / 通义等）的额度、限流、内容审核差异。
- Prompt 工程够用即可：角色、约束、示例、输出格式、失败时怎么说。少追求「神级话术」。

最小交付：

1. 封装统一的 Chat 客户端（超时、重试、token 统计、模型名可配）。
2. 一个「提取结构化字段」接口（如从用户话里抽出意图 + 槽位），带 schema 校验。
3. 同一 Prompt 在两个模型上跑，记录质量与单价差异。

过关：能画出「业务服务 → 模型网关 → 多模型」的调用图；能解释为什么不能把前端直连模型 Key。

可选加深：缓存语义相同请求；按租户/场景做模型路由。

## L2 上下文工程与 RAG

**目标：** 模型没见过的事实，靠检索和记忆补上，并且能引用、能更新、能过期。

必须掌握：

- 何时用 RAG、何时把资料直接放进上下文、何时该上知识库产品（如 Dify 知识库）。三者成本不同。
- 切分：按标题/语义切，而不是固定 500 字一刀；表格、对话、接口文档切法不同。
- Embedding 选型、向量库基本操作（写入、过滤、删除）；元数据（租户、时间、来源）必须有。
- 检索质量：召回不足 vs 噪声过多；重排（rerank）；无结果时的诚实拒绝。
- 引用与溯源：回答能指回片段；禁止检索失败还编造。
- **记忆与过期**：会话摘要、长期偏好、知识更新后旧向量必须失效。过期知识比「记得少」更危险。

最小交付：针对一份真实业务文档（接口说明、FAQ、产品手册）做问答，支持引用原文，并演示「文档更新后旧答案消失」。

过关：能诊断「答非所问」是切分问题、检索问题、还是 Prompt 没有强制引用；能说明多租户下向量必须带租户过滤。

可选加深：混合检索（关键词 + 向量）；Graph / 多跳；查询改写。

## L3 Agent、工具与工作流

**目标：** 让模型在受控工具里行动；分清「工作流编排」和「自主 Agent」，不要默认上 Agent。

必须掌握：

- Tool / Function Calling：工具 schema、鉴权、幂等、超时、对模型隐藏密钥。
- **工作流 vs Agent**：步骤稳定、要审计 → 工作流（Dify / 自研状态机）；步骤开放、要探索 → Agent。多数业务功能应是工作流 + 少量 Agent。
- 循环与预算：最大步数、最大 token、最大费用；死循环是默认风险。
- 人机交接：不确定时提问或转人工，而不是猜。
- MCP 或同等「工具/上下文标准」：把工具从业务代码里解耦，供 IDE / 运行时复用。
- 状态：线程内短期记忆、跨会话长期记忆、工具侧事实来源，三者不要混成一锅。

最小交付（三选一，做透一个即可）：

1. 带 2～3 个真实工具的 Agent（查订单/查设备/搜知识），有步数上限和工具审计日志。
2. 一个 Dify（或同类）工作流：检索 → 生成 → 结构化输出 → 业务 API。
3. 一个 MCP 工具，被 Cursor / 自建运行时同时调用。

过关：能讲清「这个需求为什么不该上 Agent」；工具失败时系统行为可预期；日志能回放每一步工具入参出参。

刻意后置：多 Agent 互相开会、无限自主规划。先把单 Agent + 工作流做稳。

## L4 多模态与实时交互

**目标：** 语音、图像进入同一条产品链路，延迟和打断成为一等需求。

有口语、设备、音色（ASR / TTS / RVC）场景时本层提前；纯文本后台可后置。

必须掌握：

- ASR / TTS 的流式与断句；VAD、打断、回声；首字/首包延迟。
- 实时对话：上行音频 → 模型 → 下行音频的状态机；弱网与重连。
- 图像：理解 vs 生成；生成内容的审核与版权边界。
- 端云分工：端上做唤醒/VAD/降噪，云上做识别与对话；设备角色、模式键、无屏交互要单独设计。
- 与文本 Agent 的统一：工具和知识不要为语音再复制一套，只换交互层。

最小交付：一条「说话 → 识别 → 对话/工具 → 播报」的闭环，能打断，能量延迟。

过关：能指出延迟预算花在哪一段（ASR、LLM 首 token、TTS）；能处理用户说一半改口。

## L5 评测、观测、成本与安全

**目标：** 没有评测的 Prompt 改动都是玄学；没有配额和降级的模型调用都是事故。

本层不要等 L1–L4 结束再学，从 L1 的第一个接口就该有：日志、token、黄金集。

必须掌握：

- **离线评测**：黄金集（好/坏 case）、回归；改 Prompt 先跑集再上线。
- 在线信号：点赞/点踩、转人工、任务成功率、检索命中、工具失败率。
- 观测：trace（一次用户请求串起检索/模型/工具）；token、费用、耗时分位数。
- 成本：按模型、租户、场景设配额与加油包；缓存、小模型预判、大模型兜底。
- 安全：提示注入、越权（工具不能比用户权限更大）、PII、未成年人与内容审核、密钥与回调鉴权。
- 降级：模型挂了走规则/检索/固定话术；绝不能把故障表现为「更聪明的胡话」。

最小交付：为 L2 或 L3 的项目加 20 条黄金集 + 一次改 Prompt 的前后对比表；再加费用日报（按模型汇总 token）。

过关：能拒绝「感觉更好了就上线」；能讲一次真实的注入或越权会怎么发生、怎么挡。

## L6 产品化架构与数据飞轮

**目标：** 智能功能像普通业务功能一样发版：多端一致、可灰度、可回滚、能从线上学习。

必须掌握：

- 模型网关：鉴权、路由、限流、审计、与业务网关分离或明确边界。
- 配置化：人设、工具开关、知识范围、模型名走配置中心，不要发版才改 Prompt。
- 多端：管理端配、B 端用、设备端播；改一处要想到调用方。
- 灰度与实验：按租户/设备/比例切模型或 Prompt；保留回滚开关。
- 数据飞轮：日志 → 坏 case → 评测集 / 知识库 / 工具补齐 → 再发版。没有闭环就没有「越用越好」。
- 与现有架构共存：领域数据仍在 MySQL / Redis / 现有 API；模型不直接连生产库。

最小交付：把一个已有智能功能做到「配置中心改 Prompt + 黄金集回归 + 配额告警」，而不是改代码发版。

过关：能画一张本团队可用的目标架构（业务服务、模型网关、知识、工作流、观测），并标明每段 SLO。

## 过关总表

| 层 | 你能独立交付 | 常见假过关 |
|----|----------------|------------|
| L0 | 流式转发服务 + 超时/429 处理 | 只会 Jupyter 里调一次 API |
| L1 | 带 schema 的抽取/对话封装，密钥不暴露 | 前端直连 Key，输出靠「请返回 JSON」 |
| L2 | 带引用的问答，文档更新后旧答失效 | 把整本手册塞进 Prompt |
| L3 | 有预算的工具循环或可审计工作流 | 套一个 Agent 框架但工具等于空 |
| L4 | 可打断的语音闭环，说得出延迟拆分 | 录音文件一次性转写再 Chat |
| L5 | 黄金集回归 + token 费用可见 + 基本安全 | 只看 Demo 好不好听 |
| L6 | 配置化 Prompt、灰度、坏 case 回流 | 每次改话术都要发版 |

## 刻意后置（先不要学）

- 从零预训练 / 全量微调大模型；需要时再学 LoRA 级适配。
- CUDA、推理框架内核、自建 GPU 集群。
- 同时深挖 LangChain、LlamaIndex、多家 Agent 框架。选定一条（工作流产品 **或** 轻量自研 + 官方 SDK）用到过关。
- 多 Agent 社团、自动写论文、自动改生产库。
- 为学 AI 把主力业务从 Java 8 整体迁到新框架。

## 推荐资源（少而精）

以官方文档和一篇长文为主，课程为辅。链接会变，以各家当前文档为准。

| 主题 | 优先读 |
|------|--------|
| 模型 API / 结构化输出 / 工具调用 | OpenAI 与 Anthropic 官方文档；国内用哪家读哪家 |
| Agent 何时用 | Anthropic《Building effective agents》 |
| MCP | Model Context Protocol 规范与示例 |
| RAG | 向量库官方 quickstart + 一篇「不要盲目 RAG」的工程综述即可 |
| 评测 | 先自己建黄金集；工具（Ragas 等）后加 |
| 观测 | Langfuse 或等价 tracing 的入门，重点是 trace 模型，不是换品牌 |
| 编排产品 | 已有 Dify 等则先吃透，再考虑自研 |
| 语音 | 所用 ASR/TTS 厂商的流式文档；WebSocket 状态机自己画一遍 |

学习时保持一个原则：**先用官方 SDK 打穿一层，再考虑框架。** 框架是加速器，不是能力本身。

## 与日常工作的对照

把路径嵌进现有交付，而不是另开一条「学习时间」：

| 你正在做的 | 对应层 | 练什么 |
|------------|--------|--------|
| 对话 / 角色 / 模式切换 | L1、L3 | 系统提示、工具、状态机 |
| 知识库 / 文档问答 / 记忆 | L2、L5 | 检索、过期、评测集 |
| 语音跟读、音色、设备端 | L4 | 流式、延迟、打断 |
| 额度、加油包、多模型 | L1、L5 | 路由、配额、降级 |
| 开放 API、多端、IoT 通道 | L6 | 网关、鉴权、多端一致 |
| Agent 运行时 / Harness | L3、L6 | 工具边界、审计、配置化 |

## 维护

能力地图相对稳；具体厂商、框架名易变。替换工具时更新对应层的「最小交付」，不要另起一份平行路径。
